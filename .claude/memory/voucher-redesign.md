**Architecture facts found (2026-11-05):**
- Redeeming already works inside the normal cart (any product or workshop): `/api/voucher/validate`, `initiate-discounted-payment` (partial), `place-order` (voucher covers the whole cart), `Orders/redeemVoucherOnOrderComplete.ts`.
- Voucher is single-use: any redemption sets status `redeemed`, so leftover value is LOST (e.g. €50 voucher on a €30 cart). €20/30/50 vouchers need a remaining-balance field.
- Cart line custom fields are copied into Stripe PaymentIntent metadata (500 chars per value, see `carts` comment in `src/plugins/index.ts`), so recipient name + note can't ride on the cart line.
- Products have `productType` (jarred/fresh/bottled/workshop/digital-course); `Orders/autoCompleteDigitalOrders.ts` is the precedent for non-shipped items.
- `/api/voucher/checkout` takes the amount from the client (1–9999): retire with the old flow.
- **Rafaela (2026-11-05): the voucher system is LIVE on main and works — reuse it, don't rebuild.** Keep: the form on the voucher page (buyer, recipient, note, delivery), code generation, `sendVoucherPurchaseEmail` (fires on voucher create → email + PDF link), `/api/voucher/generate-pdf` (her `public/voucher-template.pdf`), success-page PDF download, admin/roster. The ONLY missing piece: vouchers can't go into the cart with other items.
- Cart plan = copy the workshop pattern: held WorkshopBooking linked by `cartSlug` + 6-char `a` suffix on the cart line (`src/lib/workshopHolds.ts`), confirmed by `Orders/confirmWorkshopBookings.ts`. Voucher version: add-to-cart creates a `pending` voucher holding the personalisation; the paid order flips it to `active` (move the email trigger from create to pending→active). `/api/voucher/validate` must refuse `pending`.
- Checkout already skips the shipping address for workshop/digital-only carts (`CheckoutPage.tsx` noShipping, `autoCompleteDigitalOrders.ts`); vouchers must join that list.
